# MinuteFlow v0.14.0 — 渐进转写（macOS + Windows）

- MiMo 实时识别启用 SSE，收到增量文字立即更新临时句子，不再等待完整 JSON 响应。
- 约 1.2 秒开始提交首次预览，持续讲话每约 1.5 秒更新一次音频窗口；约 0.7 秒停顿后定稿。
- 同一路临时预览只保留最新待处理窗口，最终识别优先；并行上限三路。旧响应不能覆盖已定稿文字。
- Mac 更新预览时不再重复排序完整历史逐字稿；Windows 双来源临时文字分别显示，不再被另一路定稿清空。
- 不支持 SSE 的兼容网关保留 JSON/普通识别；认证、限流、断流不伪装成正常完成。未完成音频仍可事后补全。
- 本轮不增加声纹库，不改变既有 Token、会议文件格式、录音或总结设置。

## 体验与边界

这是“短音频上传 + 真实文字增量返回”，不是腾讯会议式持续上传音频的专用实时协议。
首次显示时间为音频窗口加网络与模型处理时间，不能保证每说一个字就立即显示。
临时文字允许修订，停顿后用最终结果替换；不做人工打字动画。
预览请求更频繁，会增加音频调用量、费用或套餐额度消耗；慢网时自动丢弃过期预览。
公开接口支持 SSE 不等于任意 Token Plan 网关都有相同能力；实际服务可能退回分段结果。

官方协议依据：https://mimo.mi.com/docs/en-US/api/audio/Speech-Recognition

## 基础验证

按本轮用户要求不扩展长时间测试。Mac 基础回归包含增量回调、持续预览、停顿定稿、
旧响应隔离、断流及兼容回退；Windows 进行编译、Core 行为检查及既有流水线检查。
没有使用用户真实音频、Token 或计费接口进行测试，真实服务延迟尚未实测。

Mac 构建包为 ad-hoc 签名，未经 Developer ID 公证；Windows 未做 Authenticode 签名。
Mac 若替换原本使用其他签名的安装，可能需要重新确认系统权限或钥匙串访问。
