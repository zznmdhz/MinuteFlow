# MinuteFlow for Mac

MinuteFlow 是一款 macOS 14+ 原生会议录音与转写工具。原始录音保存在本机；开启 AI 功能后，应用按需向用户配置的服务发送短音频片段，并可根据逐字稿生成会议纪要。

## v0.11.2 已实现

- 右侧会议名称支持自动保存：输入停顿、按回车、点击别处、切换会议时都会通过同一逻辑同步左侧标题、会议元数据和 Finder 文件夹；左侧“重命名…”保持相同行为。

- 设置 → 录音新增“整理历史会议主题”，可批量用现有逐字稿或纪要为未命名会议生成主题，并同步重命名文件夹；没有文字依据的会议会明确跳过，不会编造。

- 录音状态区改为横向紧凑布局，逐字稿使用固定高度的单一整体滚动区，不再为每段文字生成独立滚动条。
- 配置文本模型后，未命名会议会在录音结束时根据逐字稿自动生成主题，并同步重命名左侧记录和本机会议文件夹。
- 可选记录会议开始位置；地址仅写入本机会议元数据，并显示在左侧会议的日期和时长下方。
- 每场会议改为一个与左侧标题一致的扁平文件夹；旧 UUID/多层目录在启动时自动迁移，内部稳定 ID 保存在隐藏元数据中。

- 历史录音可按停顿动态分段并事后转写，逐段落盘、失败可继续；单个无文字片段会跳过，不会中断整场长录音
- 录音过程中更新或测试通过 ASR 配置后即时热启动，不再要求重新录音
- 本机加密凭据优先于残留钥匙串项，重启后稳定加载且不回显明文

- 使用 ScreenCaptureKit 录制系统声音，使用 AVAudioEngine 录制麦克风，两路原始 M4A 独立保存。
- 双路录音停止后按共同有效时间轴生成 48 kHz 双声道 `mixed.m4a`，作为完整回放；启动差、暂停/恢复、短暂缺口和单路中断通过时间轴静音对齐。
- 混音采用派生临时文件，校验成功后才原子提交；原始双轨不被覆盖。双路相加前预留音量空间，并按实际峰值缩放到约 -2 dBFS。
- 开始、暂停、继续、停止、菜单栏控制、实时音量、单路失败时降级继续录制。
- 录音文件按“日期时间 + 会议名称 + 声音来源”自动命名，并可在应用内播放或定位到 Finder。
- 全部历史会议可以重新打开、重命名和完整删除，删除范围包括原音频、逐字稿和纪要。
- 一个 AI 服务页面只填写一次 Base URL 和 Token；ASR 与总结共用该连接。
- 自动识别 MiMo Token Plan 地址，并用 `api-key` 请求头、`/chat/completions` + `input_audio` 调用 `mimo-v2.5-asr`。
- 其他自定义服务默认使用 OpenAI Compatible `/audio/transcriptions`，总结使用 `/chat/completions`。
- 内置真实连接测试：生成一段中文测试语音验证 ASR，并用短逐字稿验证总结模型。
- 转写采用“临时预览”和“最终段落”两层结构：连续讲话约 3 秒显示一次不落盘的预览，约 0.7 秒自然停顿后定稿，不再每 3 秒永久切断句子。
- 动态分段会持续学习房间底噪；即使环境噪声导致停顿判断不清，连续讲话也会按约 40 秒的可读上限形成新段落，不再产生几十分钟的一整段文本。
- 连续讲话安全上限默认 15 秒；极长讲话使用约 450 ms 重叠切片并去重，乱序返回后仍按音频时间组装为同一段落。
- 录音结束后在本机检测有效音轨并进行声学说话人聚类，生成带时间戳的“说话人 1/2…”逐字稿；说话人可在会议内重命名，分析结果保存在 `diarization.json`，不上传声纹。
- 若系统声或麦克风整段接近数字静音，会议页会明确提示，不再把“权限已开”和“实际录到了声音”混为一谈。
- ASR 返回中的重复协议标记（例如连续的 `<chinese>`）会在保存前清理。
- 每个最终段落保留各次 ASR 原始响应、时间、切片原因和重叠信息，编辑与规范化不覆盖识别证据；旧版逐字稿继续兼容。
- 逐字稿保留“原始识别”，允许直接编辑，并可生成不覆盖原文的“规范化”版本。
- 权限页明确显示麦克风和屏幕/系统音频权限，并提供五秒双路录音自检与回放。
- 打开主窗口、设置窗口和被动刷新不会调用受保护的 ScreenCaptureKit API；只有开始录音、主动验证或五秒自检才会请求/验证权限。
- API Key / Token 只在点击“保存”时写入，默认仅使用 macOS 钥匙串。钥匙串失败时不会静默降级；只有用户阅读安全提示并再次确认后，才使用 AES-GCM 加密的用户私有文件，不写入会议文件或日志。
- Token 保存后立即回读验证，重新打开时不把明文重新填入输入框，但录音和连接测试继续使用已保存值。
- ASR 上传限制为最多两个并发任务，并设置有界等待队列、请求超时、15 秒全局收尾上限和 429/5xx/网络错误重试；无法识别的 WAV 与不含 Token 的处理清单会保存在本机待处理目录。
- 异常退出遗留的活动会议会恢复为“已中断”，不会锁死下一次录音；旧会议总结完成也不会覆盖正在录制的新会议。
- 长逐字稿会按约 24,000 字符分段生成阶段摘要，再合并为最终纪要，避免一次请求超过模型上下文。
- 逐字稿和历史列表不再静默截断，编辑保存使用防抖以避免每输入一个字符都重写整个文件。

## 为什么仍有两个模型名称

这里不是两个服务配置。Base URL 和 Token 只填一次，但两项任务的模型职责不同：

```text
系统声 / 麦克风
    ├── 本地 M4A 原始录音
    └── 动态 WAV 短片段 → ASR 模型 → 可编辑逐字稿
                                      └── 文本模型 → Markdown 会议纪要
```

`mimo-v2.5-asr` 是专门的语音识别模型；会议总结需要当前 Token Plan 套餐支持的文本模型。关闭“会议总结”后只需填写 ASR 模型，不需要填写总结模型。

## MiMo Token Plan 配置

在“设置 → AI 服务”中填写：

1. Base URL：Token Plan 页面给出的 OpenAI Compatible 地址，例如中国区 `https://token-plan-cn.xiaomimimo.com/v1`。
2. API Key / Token：Token Plan 页面生成的 `tp-...` Token。
3. ASR 模型：`mimo-v2.5-asr`。
4. 如需纪要，再开启“会议总结”并填写套餐支持的文本模型。
5. 点击“测试当前配置”，分别查看语音识别和总结的真实返回与耗时。

应用会从 Base URL 自动派生请求地址；用户不需要手工填写完整 `/chat/completions` 接口。

没有有效 Token 时，录音仍会完整保存在本机，但不会上传音频、生成逐字稿或会议纪要。

## 数据目录

默认会议目录：

```text
~/Library/Application Support/MinuteFlow/Sessions/项目周会/
├── 2026-08-24_1430_系统声音.m4a
├── 2026-08-24_1430_麦克风.m4a
├── 完整回放.m4a
├── 逐字稿.md
├── 逐字稿.json
├── 会议纪要.md
├── AI排版文稿.md
├── 说话人时间轴.json
└── 混音时间轴.json
```

同名会议会自动追加“(2)”“(3)”，并同步显示在左侧，保证文件夹名称与会议标题始终一致。`.minuteflow-session.json` 是 Finder 默认隐藏的内部关联文件，不包含 Token。

启用 ASR 后，临时 WAV 片段会发送到所选服务，识别完成后从临时目录删除。多次重试仍失败或停止时未完成的最终片段与处理清单保存在 `~/Library/Application Support/MinuteFlow/PendingTranscriptions/`；临时预览不会落盘。原始 M4A 始终保留。启用总结时，最终逐字稿文本会发送到同一服务连接中的总结模型。

## 运行与测试

使用 Xcode 打开 `MinuteFlow.xcodeproj`，选择开发团队和“My Mac”后运行。首次录音需要授予麦克风与屏幕/系统音频录制权限；开启会议位置时还会请求定位权限。macOS 更新屏幕录制权限后，需要完全退出再启动一次。

也可以执行：

```bash
swift test
```

测试覆盖权限无副作用读取、音量计算、WAV 转换、自然停顿/临时预览/硬上限重叠转写、乱序组装、双路时间轴与离线混音、峰值保护、原文件不变、双路协调与运行中降级、异常退出恢复、跨会议总结竞态与长文本分段总结、会议持久化与删除、Token 显式保存/加密回退/跨启动、Token Plan 接口解析和旧数据兼容。

## 当前边界

- 当前是“约 3 秒临时预览 + 自然停顿最终定稿”的非流式近实时转写，并非豆包输入法式的逐字流式识别；实际延迟还取决于网络与模型响应。
- 说话人区分采用本地声学聚类，不是身份鉴定：它无需上传声纹，但在多人重叠讲话、极短插话或音质较差时可能需要用户修正说话人名称。现有 ASR 服务没有返回逐词时间戳时，说话人切换精度受约 15 秒识别片段边界限制。
- 自定义服务必须兼容当前使用的 OpenAI 音频转写与 Chat Completions 请求格式。
- 远程模型的可用性、计费、速率限制和数据留存由对应服务商决定。
- 本仓库生成的本机测试包使用固定的本地签名身份，解决同一台 Mac 上预览版身份随构建变化的问题；向其他 Mac 正式分发仍需 Apple Developer ID 签名与公证。
