# MinuteFlow for Windows

Windows 10/11 x64 桌面应用，WPF + .NET 10，音频由 WASAPI/NAudio 采集。
与 Mac 使用相同产品版本和 GitHub Release。安装包包含运行时，不需要安装
.NET SDK、虚拟声卡或 FFmpeg。

## 安装与使用

1. 下载 `MinuteFlow-v0.14.0-Windows-Setup.exe` 并安装。默认仅安装到当前用户，
   不要求管理员权限。也可解压 `MinuteFlow-v0.14.0-Windows-win-x64.zip`，
   直接启动其中的 `MinuteFlow.exe`。
2. 在「设置与检测」保存 Base URL、Token、ASR 模型、文本模型。Token 输入框
   重启后空白是正常行为，已保存的值由 Windows 当前用户 DPAPI 解密使用。
3. 选择声音来源。系统声音来自 Windows 默认播放设备；麦克风可在设置选择。
4. 录音时可暂停/恢复，结束后保留分轨并生成完整回放。模型故障不丢录音，
   已保存录音可用「补全整段录音」补写缺失区间。
5. 已保存标题双击后编辑；会议、目录、左侧名称同步。仅查看不更改文件日期。
6. 历史会议支持右键管理、文件定位、导入 WAV/M4A、逐字稿编辑/原文恢复、
   本地说话人分析、AI 主题、纪要及排版文稿。

语音模型按钮使用静音测试调用检查协议与认证，另可选择自己的 WAV 测试实际
识别。五秒自检时播放电脑声音并说话，以确认采集到真实声音。

实时识别约 1.2 秒开始请求临时文字，每约 1.5 秒刷新音频窗口；MiMo 支持时
通过 SSE 逐步更新文字，停顿约 0.7 秒后整句定稿。识别请求最多三路并行，
待处理预览只保留每个来源最新的一段，定稿优先，避免慢网积压临时请求。
这是短音频上传后的文字流，不是持续上传音频的全双工协议；实际延迟取决于
网络及模型。预览刷新会增加调用量和费用/配额消耗。

## 数据与保护

- 默认目录：`%LOCALAPPDATA%\MinuteFlow\Sessions`，每场会议一个扁平目录。
- Token：`%LOCALAPPDATA%\MinuteFlow\credential.dpapi`，不会放入会议目录。
- 原轨/回放采用单声道 48 kHz PCM16 WAV；约 346 MB/小时/文件。两路录音及
  完整回放合计约 1 GB/小时，请保持足够空闲空间。
- 默认连续 30 分钟无有效声音自动暂停，可改为 60 分钟或关闭；声音恢复不会
  自动恢复录音。休眠、全部设备失效和写盘失败也会暂停并提示。
- 为避免传统 WAV 的 4 GiB 上限，单场有效录音达到 10 小时会暂停；请结束
  保存后新建下一场。持续噪音可能阻止无声保护触发，容量保护仍会生效。
- 删除会议移至应用自己的 `.Trash`，可从数据目录恢复；卸载保留会议和凭据。
- 默认关闭主窗口保留托盘，真正退出有保存/取消提示。

## 双平台交换与差异

可复制整场会议目录在两端读取。支持旧 Mac `file:` URL 重定位、相对 WAV 路径、
小数秒 ISO8601 日期及两端混音/说话人时间轴；不得只复制元数据而遗漏音频。
本次不提供云端同步或两台机器同时编辑同一文件夹。

Windows 自动地点记录尚未实现；显示「地点未记录」。设备切换后需要暂停并
检查设备，不能承诺自动迁移到新声卡。说话人标签是本地近似声学聚类，可手工
校正，不能作为身份鉴定。远程识别准确率取决于音频及用户所配模型。

Windows 安装程序尚未 Authenticode 签名，可能出现 Windows 下载/运行提示。
只从项目官方 Release 获取软件并核对 SHA256；这里不要求关闭系统保护。

## 构建与验证

```powershell
dotnet run --project windows/tests/MinuteFlow.Core.Tests -c Release
./scripts/build-windows.ps1
```

安装包构建需要 Inno Setup 6。CI 在实际 Windows 环境执行 DPAPI、文件混音、
转写取消等行为检查，运行 WPF 窗口检查并验证安装/卸载。真实麦克风、声卡、
蓝牙和长录音的硬件表现仍应在目标机器检查，详见独立验证记录。
